How the keys are made
  1. The wallet picks 12 or 24 random words from the standard BIP-39 list. The last word carries a checksum.
  2. Your add-on phrases are joined in order (add-on 1, then 2, then 3, no separator) into one passphrase. Empty fields are skipped.
  3. PBKDF2-HMAC-SHA512 with 2048 rounds turns the words and passphrase into a 512-bit seed.
  4. BIP-32 turns the seed into a master key. The path m/44'/60'/0'/0/n selects account n.
  5. That account's private key gives the public key (secp256k1), and Keccak-256 of the public key gives the Ethereum address.

Because the add-ons become a standard BIP-39 passphrase, the same words and add-ons give the same Ethereum account in other BIP-39 tools that accept a passphrase. This page's output matches published test vectors (see the self-test).

Limits of this demo
  • The elliptic-curve and Keccak code is hand-written and not audited. A real wallet should use audited libraries.
  • A wrong add-on does not produce an error. It opens a different, empty wallet. Compare the check value shown when you created the wallet.
  • PBKDF2 with 2048 rounds is cheap to attack, so short add-ons chosen by a person can be guessed. A production vault mode should stretch the add-ons with Argon2id.
  • Secrets stay in this page's memory until you lock the wallet or close the tab.
  • Only Ethereum is derived here.
